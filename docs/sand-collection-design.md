# 沙画收集游戏：规则分析与技术方案

依据：用户提供的《顶级消除秀》两张第 17 关截图，以及用户对前排桶、六个传送带位置、按颜色收集底部沙子和沙粒滑落的说明。本文记录规则与实现方案，不代表已验证原作全部规则。

## 当前原型

已实现游戏入口 `#/play/sand`：八幅原创沙画（3～8 色）、四列前排桶、六位横向传送带、底部六层同色收集、三桶合成、满桶立即释放、堵塞与通关判定、全部关卡开放、暂停和重开确认。桶不要求相邻，大桶可再次合成；未加入钥匙、锁和道具。

性能实现采用休眠行而非分块：只有变动附近的行进入重力扫描，列底部高度通过脏标记更新；网格只在变动后上传像素缓冲，暂停与待开始状态停止重复绘制。画布缓冲固定 720×800，装饰流沙粒子最多 96 个。画布以 object-fit:contain 等比显示，避免手机可用高度变化时压扁桶子；待选 SVG 桶与传送带 Canvas 桶共用 bucket-art.ts 轮廓，包含提手、高光与容量标签。Canvas 桶沿用同一桶口锚点，改变外形不改变收集坐标。

规则验证包括六层边界、合成容量守恒、六桶限制、满桶即时释放、未满桶循环和八个关卡的确定性通关回放。手机尺寸浏览器验证不能替代真实低端手机性能验证。

新增关卡包含爱心花园、向日葵、彩虹、冰淇淋、蝴蝶、火箭、狐狸与八色花瓣。桶容量以 200、400、600、800、1000、1200 为主，尾桶按该色剩余沙量补齐；四列混排，不再为每种颜色固定一列。挑战关使用 7～8 色，超过六个传送带位置，需要观察颜色露出与队列次序。所有关卡直接可选。

传送带速度提升一倍：30 Hz 下完整周期为 180 步，向右可见移动约 3 秒，隐藏回程约 3 秒。空传送带不再绘制提示文字。新桶使用独立行程，从可见左侧入口立即出现；连续点选按桶宽错开，不再根据全局时间或占位编号直接放到隐藏回程。关卡队列离线生成，运行时不求解；测试使用独立通关回放验证正式队列，每色容量严格匹配沙量。

桶区的“第一排”按每列最前端定义：一列取走前桶，下一桶立即成为该列可选项，不要求先清空另外三列。锁作为该列队首障碍时，阻挡后面的桶。

钥匙、锁和道具先保留扩展接口，不能仅凭图标确定作用。三个同色桶自动合成已由用户确认，属于首版核心规则。

## 2. 核心循环与策略

观察底部六层内的颜色 → 选一个可用的前排桶 → 占用传送带位置 → 检查三桶合成、释放两个位置 → 桶移动到可收集位置 → 吸取范围内同色沙子 → 满桶立即消失、释放位置 → 上方沙子下落 → 新颜色进入收集范围 → 继续选桶。

玩家要同时判断三件事：这个桶能不能马上收集；取走它以后能解锁哪个后排桶；它要等待多久才能装满、会占用多少缓冲空间。

例如白沙埋在底部六层范围以外：提前上白桶暂时只能占位；先收走底部颜色，白沙下落、进入范围后，白桶才能收集。若白沙已在底部六层内，本次试验允许直接收集，即使其下方还有其他颜色。上一个暂时用不到的桶也可能露出后排关键桶，或者凑齐三桶合成以腾出位置。

难度主要来自沙子的颜色遮挡、桶的队列顺序、桶容量和六个位置的约束。传送带速度与收集速度是节奏参数，不能替代上述策略关系。

## 3. 技术选型

沿用当前项目的 Vue 3、TypeScript、Vite。沙画、流沙、传送带和活动桶用 Canvas 2D 渲染；待选桶、按钮、进度、说明和结算用 Vue 组件。

沙粒物理使用离散网格元胞模拟。首版用 160×160 网格作为可调起点；1 个非空格保存 1 个颜色编号，逻辑上计为 1 单位沙子。400、800 可作为桶容量，但原作数字与屏幕像素的真实换算尚未确定。

不为每颗沙子创建 Vue 节点或 Matter.js 刚体。现有 Matter.js 可用于其他游戏，本玩法的颜色遮挡与数量守恒更适合直接用网格处理。

物理固定 30 步/秒，画面由 requestAnimationFrame 绘制；这只是初始配置，需要在真实手机上测量后调整。关卡模拟不依赖屏幕像素尺寸。

## 5. 沙粒物理与底部收集

### 下落

每次从下向上扫描沙场。下格空则下落；下格被占用则检查左下、右下，随机选择可落方向；都不能落则保持位置。交替扫描方向并使用带种子的随机数，避免长期向一侧偏斜，同一颗粒每步只移动一次。

黑色、白色、绿色、青色等都按同一套重力规则处理。截图中的黑色外框属于图案颜色，首版不会自动当成刚性障碍；图案外的装饰边框才属于容器。

关卡启动先保留沙画原样。底层被收集后，网格出现空位，再触发重力更新。初始图案应构成稳定沙场：图案内看似“背景”的颜色也可能是沙子，不能随意转换为空格。若美术图自带悬空区域，需要在制作关卡时明确填充、预沉降或其他支撑规则。

### 底部六层收集范围

针对桶口所在横向范围，查询每列最下方沙粒所在行 `bottomY`。本步收集范围固定为 `max(0, bottomY - collectDepth + 1)` 到 `bottomY`，首版 `collectDepth = 6`。每列按自己的底部高度计算，不按整个画面的统一水平线计算。

- 范围内与桶同色的沙粒：可以收集，一步可收集多层，但受吸取速率与剩余容量限制。
- 范围内不同颜色的沙粒：保留；首版试验允许继续检查这六层内的其他位置，不沿用先前“遇到异色立即停止”的单层假设。
- 空格不含沙量，但仍占一个网格深度；不会为凑够六颗沙子而扩展到更高位置。
- 第七层及以上、桶口横向范围外的同色沙子：本步不能收集。

每步先建立收集范围快照，再向活动桶分配范围内的同色沙粒，吸取数量不得超过吸取速率与剩余容量。各桶共享这次范围快照；同一步内不因删除沙粒反复重算底部并向上推进，避免无限向上吸取。收集后移除满桶，再更新重力；下一步重新计算底部六层。首版不使用整片同色连通删除。

“六层”是用于试手感的网格参数，不声称是原作精确规则。网格分辨率改变时，应重新评估实际吸取深度；原型可对比不同深度，随后调整收集速度与关卡桶序列。

桶移动时其吸取范围随位置变化。吸取半宽与绘制的桶口宽度一致；装饰沙流以桶标识持续追踪当前桶口，并按大桶缩放更新落点，不能锁定吸取开始时的旧坐标。桶满、合成移除或进入隐藏回程时立即清理对应粒子；如果动态观察确认原作允许跨位置吸取，再改变这一策略接口。

### 数量与动画

成功收集时，在同一个逻辑操作中删除网格颗粒，并减少桶的剩余容量。流入桶的粒子只是视觉反馈，不再重复参与计数。

始终保证：初始沙量 = 当前网格沙量 + 已收集沙量；每个桶的已收集量不超过容量，同一颗沙子只能分配给一个桶。同色桶范围重叠时按确定顺序轮转分配。

## 6. 传送带、暂停与胜负

桶处于进入和收集状态时占用位置，活动桶总数不得超过 6。桶的剩余容量减到 0 时，在该逻辑操作中立即从传送带移除并释放位置，不等待退出动画。完成特效是独立的视觉事件，不参与占位或后续收集。点击上带是原子操作：检查队首与空位、预留位置、移出队列、露出下一项、执行三桶合成，连续点击不能重复取桶或产生第七个桶。

### 三个同色桶合成

首版约定凑齐任意三个传送带上的同色桶便自动合成，不要求相邻，也不要求未升级桶；只统计已经上带、仍有剩余容量的桶，不统计待选队列或完成特效。已形成的大桶也可参与下一次三桶合成。

合成保留最早上带桶的标识，删除另外两个；如果保留桶正在隐藏回程，则移到参与合成的可见桶位置，确保合成结果立即可见。新桶总容量等于三者总容量之和，剩余容量等于三者剩余容量之和，已收集量因此完整保留。大桶仍占一个位置，收集中心与渲染共用归一化位置，按沙粒像素中心映射；普通桶的桶口有效半宽为画布逻辑坐标 17，大桶随 1.09 倍视觉尺寸同步扩大。移动速度与普通桶一致。

例如三个容量为 400、800、800 的同色桶，分别已收集 100、300、200：合成后容量为 2000，已收集量为 600，剩余容量为 1400；占位从三个变成一个，立即释放两个位置。

有多组合成时按上带顺序确定每组三桶，重复执行直到不足三个同色桶。满桶完成应先移除，不让已经完成的桶参与合成。合成与占位更新在同一逻辑事务内完成，合成动画不延迟释放位置；视觉粒子以独立坐标继续飞向合成后的桶，避免删除旧桶后引用失效。

已经满六桶时不允许先上第七桶再合成；只有第六桶上带后凑齐三桶，才能从六桶变为四桶。

用户已确认未满桶到尽头后再次收集并持续占位。根据最新截图反馈，画面只显示一条从左向右的横向传送带：桶到右侧后消失，回程隐藏，再从左侧出现。隐藏期间不收集，保留剩余容量并持续占位；满桶立即移除。

暂停、页面失焦或切入后台时，停止沙粒、传送带与收集；恢复后清除时间积压，避免补算后台期间的动作。

六个位置满时先执行可发生的三桶合成与满桶即时移除；若仍满则禁止上新桶，不能立即判失败，因为现有桶可能正在收集。首版只在沙场稳定、没有上带或合成事件，并确认所有活动桶在一个完整循环内都没有可收集目标且不可能释放位置时判为堵塞。该检查可在克隆状态中完成，避免让玩家实际等待一整圈；钥匙与锁加入后也必须纳入可执行动作判定。

首版胜利目标拟为清空沙画，完成最后的结算动画后通关。若原作还要求全部桶完成，则另加对应条件。无匹配桶但仍有残沙、空列与锁导致无合法动作等情况也需要明确处理，不能永久卡在“运行中”。

## 7. 关卡制作与可解性

先做少量手工关卡验证核心体验，不直接随机生成图案与桶序列。

沙画素材可以由低分辨率 PNG 量化到限定调色板，再转换为颜色网格；只导入沙场素材，不把截图中的文字、装饰和桶混入沙画。初期用原创几何图案更容易精确控制沙量。

每种颜色的桶容量总和，应与该颜色的沙量一致；数量匹配只是必要条件。颜色埋藏关系、桶队列、六个位置和上带时机仍可能造成无解。

每关保存至少一组带时机的通关操作，用同一个引擎和关卡种子回放，检查真的能够清空且全程不超过六个桶。回放必须包含六层收集、三桶合成和满桶即时移除规则；调整物理、速度、收集深度或桶口范围后重新回放。首版固定种子，后续要引入随机物理时，再针对多个种子验证容错。

关卡递进建议：两色少量沙、无遮挡 → 三色底部深度限制 → 三桶合成教学 → 后排关键桶与四列选择 → 不同容量与位置规划 → 再加入已确认规则的钥匙与锁。

## 8. 实施顺序与验收

1. 可调试的核心场景：四列桶、六个位置、底部六层收集、三桶合成、满桶即时消失、循环传送带、重力、暂停和重开。
2. 规则验证：调整横向吸取范围与六层手感，核实堵塞判定，加入自动守恒测试与解法回放。
3. 可玩的关卡版：原创沙画、关卡进度、胜负、适配手机并接入游戏列表。
4. 表现与扩展：桶的填充动画、流沙声、分数和连击；确认原作行为后再加入钥匙、锁及道具。

验收重点：第六层同色沙可收集，第七层本步不可收集；异色沙保留；同一步不重复扩展深度；收集后上层确实下落；后排桶不可点击；单列队首推进正确；快速点击最多六桶；三桶合成总容量、剩余容量与已收集量守恒并立即释放两个位置；大桶可再次合成；满桶即刻消失且立即可上新桶；满位仍能正常完成当前收集；重开清除旧状态；暂停后状态不变；每关至少一组解法回放成功；真机运行没有持续卡顿。

## 9. 实现前尚需确认

未满桶循环且持续占位、满桶立即消失、三个同色桶容量相加合成已经确认。收集深度按用户要求先试六层；六层内部允许跨过异色、合成不要求相邻、大桶可再次合成属于当前明确写出的原型约定，可根据试玩修改。尚需动态核实桶口能吸取多宽、满六桶时是否有宽限时间、最终通关目标。钥匙获得与锁的消耗方式、分数连击和三种道具可在基础玩法完成后单独核实。

以上待确认项采用可替换策略和配置保存，避免把未经观察的行为写死在沙粒引擎中。
